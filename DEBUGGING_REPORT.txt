================================================================================
                              THE BUG IN BRIEF
================================================================================

Location: QueueRepository.hasPhaseCompleted() [line 197-206]

Root Cause:
  - Method returned TRUE (phase complete) when phase was EMPTY (0 items)
  - This caused engine to skip Phase 1 and jump to Phase 2
  - Phase 2 tried to spend from an unfunded UTXO address
  - Result: Infinite retry loop with "No UTXOs available"

Why It Happened:
  Query: SELECT COUNT(*) WHERE status != 'COMPLETED'
  If 0 items exist → COUNT = 0 → Return true (phase complete)
  But empty phase should return FALSE (not complete)

Impact:
  - 9,533+ consecutive failures over 5-10 minutes
  - Logs filled with repeated error messages
  - Deal stuck in SWAP stage, unable to process

================================================================================
                            THE FIX EXPLAINED
================================================================================

Before (Broken Logic):
  ┌─ Does phase have ANY items with status != 'COMPLETED'?
  │
  No items at all?        → COUNT = 0 → Returns TRUE (wrong!)
  All completed?          → COUNT = 0 → Returns TRUE (correct)
  Some pending?           → COUNT > 0 → Returns FALSE (correct)

After (Correct Logic):
  ┌─ Do items exist in this phase?
  │
  ├─ NO (0 items)         → Return FALSE (empty, not complete)
  │
  └─ YES (items exist)
     ├─ Are ALL completed?  → Return TRUE (complete)
     └─ Are SOME pending?   → Return FALSE (not yet complete)

Fix #1: QueueRepository.hasPhaseCompleted()
  - Count total items first
  - If 0 items → return false (empty phase, not complete)
  - If items exist → check if all are completed

Fix #2: Engine.processQueuesPhased()
  - Added explicit empty phase handling
  - Case 1: Items pending → process
  - Case 2: Items completed → move to next phase
  - Case 3: Empty → skip to next phase

================================================================================
                         KEY TAKEAWAYS
================================================================================

Bug Class: Logic Error in Empty Collection Handling
Root Cause: Used negative existence check on empty set
Lesson: Always distinguish between "not found" and "doesn't exist"

Bad Pattern:
  return collection.filter(x => x.status != 'done').length === 0

Good Pattern:
  const total = collection.length
  if (total === 0) return false  // empty, not complete
  const done = collection.filter(x => x.status === 'done').length
  return done === total  // all complete

Impact Factors:
  - Only visible when Phase 1 had items but escrow unfunded
  - Production bug (not caught in dev)
  - Critical severity (blocks deal processing)
  - Easy to reproduce (just don't fund escrow)
