ROOT CAUSE (Simple Explanation)
================================================================================

The system was checking "current balance" in WAITING stage, which changes based
on confirmation threshold. When the threshold increased from 0 to 2 confirmations,
the visible balance dropped, even though the funds were still in the blockchain.

The system incorrectly interpreted this balance drop as evidence of a reorg and
reverted the deal, when it should have just waited for confirmations to accumulate.


ROOT CAUSE (Technical Explanation)
================================================================================

In COLLECTION stage: minConfirms=0
  → Show all deposits: 0.10054 ALPHA ✓

In WAITING stage: minConfirms=2
  → Show only deposits with 2+ confirms: 0.01502486 ALPHA
  → Other deposits just need 1 more block for confirmation
  → Old code checked: "0.01502486 < 0.1003 required → REORG!"
  → Correct behavior: Wait for confirmations, don't revert!


THE FIX
================================================================================

File: /home/vrogojin/otc_agent/packages/backend/src/engine/Engine.ts
Lines: 275-322

Changed from:
  1. Check balance with high confirmation threshold
  2. If balance insufficient → REVERT (false REORG)
  3. If balance sufficient → Check locks

Changed to:
  1. Check locks (confirmation readiness) only
  2. If locks ready → SWAP
  3. If locks not ready → Wait (don't revert!)

Compiled Code: VERIFIED (contains new logic, old logic removed)
