6. ROOT CAUSE - WHY VESTING TRACER RETURNED 'UNKNOWN'
================================================================================

The VestingTracer returned 'unknown' because:

1. It successfully traced the transaction chain to the coinbase
2. It found the coinbase transaction
3. But it could not determine the block height because:
   - Electrum response lacked explicit height fields
   - Fallback methods were incomplete

Electrum Response Missing Fields:
  - height: undefined
  - blockheight: undefined
  - block_height: undefined

Available Fallback Methods (Before Fix):
  1. Direct fields (unavailable)
  2. Derivation from confirmations (WORKS - but wasn't the issue)
  3. Block header fetch (possible but additional RPC call)
  4. Coinbase field extraction (MISSING - not implemented)

The issue was that if Fallback 1 or Fallback 2 methods failed, there was no
Fallback 3 to extract the block height from the coinbase field itself.

================================================================================
7. SOLUTION IMPLEMENTED
================================================================================

Added Fallback 3 Block Height Extraction Method

File: packages/chains/src/utils/VestingTracer.ts
Lines: 199-220

Method: Extract block height from BIP141 coinbase field
- Parse the coinbase hex field
- Extract block height (first 1-9 bytes encode the height in little-endian)
- Convert to integer for vesting status determination

Key Benefits:
  - No additional RPC calls needed
  - Always present in coinbase transactions
  - Reliable method per Bitcoin protocol (BIP141)
  - Provides complete fallback chain for all Electrum server implementations
